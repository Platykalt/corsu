# Minecraft Java: several game versions from one translation

Status: in progress (October 2026). This page is the contract between the tools, the data and the installer.

## Measured starting point (2026-10-17)

Mojang's English of every release from 1.6.1 to 26.2 (87 versions, client jars read with HTTP range requests),
compared with 26.3, key and text:

| Family | Versions | Keys per version | Same key and text as 26.3 |
| --- | --- | --- | --- |
| JSON (`en_us.json`) | 1.13 to 26.2 | 3,988 to 8,123 | 87 % (1.13.2) to 99 % (26.2) |
| `.lang` (`en_us.lang`, `en_US.lang` up to 1.10.2) | 1.6.1 to 1.12.2 | 1,362 to 3,303 | 21 % (1.6.4) to 26 % (1.12.2): keys were renamed in 1.13 |

Unique (key, English text) pairs over all those versions: 12,461; not in 26.3: 3,902 (about 17,000 words):

| Kind | JSON family | `.lang` family |
| --- | --- | --- |
| Key in 26.3, English changed (review, adapt) | 687 | 195 |
| Same English under another 26.3 key (check the family before reusing) | 81 | 1,680 |
| Text found nowhere in 26.3 (translate) | 245 | 1,014 |

Before 1.6.1 there are no resource packs: adding a language needs another mechanism (not handled). Snapshots,
pre-releases and release candidates (755 snapshot entries in Mojang's manifest) are inventoried separately and not
claimed as supported.

## Data (committed; Mojang's texts never are)

- `co_fr.json`: the 26.3 translation, the base.
- `keys.tsv`: every (key, English hash) of every handled release, with the versions where it appears. Columns:
  `key`, `hash` (first 12 hex digits of SHA-1 of the UTF-8 English text), `versions` (comma-separated release ids).
  Generated by `tools/mcversions.py index`; lets Corsu build any version's pack offline.
- `versions.json`: one entry per release id: `lang_format` (`json` or `lang`), `lang_file` (path inside the pack),
  `language_code` (as written in `options.txt`: `co_fr`, or `co_FR` up to 1.10.2), `pack_format`, `mcmeta`
  (`pack_format`, `supported_formats` or `min_max`), `supported` (true only when a pack is built and checked),
  `coverage` ({`translated`, `total`}), `note`.
- `history.json`: Corsican for pairs that differ from the 26.3 base:
  `{key: {hash: {"co": text, "kind": "reused|renamed|adapted|new", "from": "26.3 key or null", "review": "ai|human",
  "note": "..."}}}`. A correction to a shared text is made once, on its (key, hash) pair, and reaches every version
  showing that exact text; a different English text is a different pair, so a historical difference stays.

Resolution for version V, key k with English hash h: `history[k][h]` if present, else the base translation when
26.3's English for k has hash h, else nothing (the game shows English for that key).

Validation is kept per pair and never copied to another pair: translation present, AI review, human review, seen in
the game (recorded per version in `versions.json` notes and `STATUS.md`).

## Interfaces

- `src/minecraft_packs.py` (runtime, offline, standard library): `target(version) -> dict | None` (the
  `versions.json` entry when supported), `build_pack(version) -> (bytes, report)` (report: `translated`, `total`,
  `missing` count), `base_version(text) -> str | None` (normalise ids such as `fabric-loader-0.16.9-1.21.1`).
- `src/minecraft.py` (installer): finds game folders and their base versions (Prism Launcher, MultiMC, official
  launcher, loaders), asks `minecraft_packs.target` and `build_pack`, installs `resourcepacks/corsu-minecraft-java.zip`
  and the version's `language_code`, and reports per folder: version, coverage, result, reason.
- `tools/mcversions.py` (maintenance): `fetch`, `index`, `formats`, `build VERSION|all`, `verify VERSION|all`.
- `tools/mchistory.py` (maintenance): classify pairs (reusable, renamed, absent from 26.3, changed, ambiguous) and
  report; writes nothing in `history.json` without a decision recorded in it.
